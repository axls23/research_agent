Gemma 4 12B Q4_K_XL vs Q8 MTP Assistant

2K-class input / 2048-token output benchmark at 64K context. Draft max 2, drafter top-k forced to 1 in the MTP implementation, accepter temperature 0.6. Generated 2026-06-03T14:21:09 local time.

Result: Q8_0 MTP was active and accepted draft tokens, but remained slower than target-only. Coding generation ran at 44.93 tok/s target-only vs 39.54 tok/s with MTP. General generation ran at 44.31 tok/s target-only vs 35.97 tok/s with MTP.

Configuration

  • Target: gemma-4-12b-it-UD-Q4_K_XL.gguf
  • Assistant: gemma-4-12B-it-assistant-Q8_0.gguf
  • Context: 65536; batch 4096; ubatch 512; flash attention on
  • MTP lane: --spec-type draft-mtp, draft max 2, draft KV q8_0/q8_0
  • Drafter sampler patch: MTP top_k changed from 10 to 1 in common/speculative.cpp
  • Accepter generation: n_predict=2048, temperature=0.6, server --ignore-eos

Interpretation

Draft max 2 plus top-k 1 raised acceptance compared with the previous top-k 10 / draft max 3 run, especially on coding, but the assistant overhead still exceeded the accepted-token savings for these prompts on this machine.

Because temperature=0.6 was requested for the accepter, this run is a sampled throughput comparison, not a deterministic equivalence test.
